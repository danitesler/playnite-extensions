# Contributing

Thanks for helping out. This is a solo-maintained project, so small,
focused PRs are easiest to review.

## Before you start

- For bugs and ideas, [open an issue](https://github.com/danitesler/playnite-extensions/issues) first.
- For security issues, see [SECURITY.md](SECURITY.md) — do not open a public issue.
- Check `src/extensions.json` for the add-on `key`, `kind`, and `dir`.

## Setup

- Windows for building (Playnite is Windows-only).
- .NET 8 SDK (`dotnet test` uses `tests/Tests.csproj`).
- Node 20 for `npm run check:readmes` and theme preview scripts.
- Full agent conventions live in [AGENTS.md](AGENTS.md).

## Plugins (`src/<Name>/`)

```pwsh
./scripts/validate-extension.ps1 -Extension <key> -Mode Ci
./scripts/build-plugin.ps1 -Extension <key>
dotnet test tests/Tests.csproj -c Release
```

## Themes (`src/themes/<Name>/`)

```pwsh
./scripts/validate-extension.ps1 -Extension <key> -Mode Ci
./scripts/build-theme.ps1 -Extension <key>
```

```bash
npm run check:tokens
npm run check:layout
```

Screenshots are generated from HTML previews, never from live Playnite windows:

```pwsh
./scripts/take-screenshots.ps1 -Extension <key>
```

After token or XAML changes, re-run validation and re-render previews.

## READMEs

Do not hand-edit generated files (marked `Generated by`):

```bash
node scripts/generate-readmes.mjs
npm run check:readmes
```

The root table rows and per-add-on pages are produced from
`info/danitesler_<key>.yaml`, manifests, and git tags.

## PR guidance

- One add-on per PR when possible.
- Include: what changed, how you validated, screenshots for theme UI changes.
- Do not commit `bin/`, `obj/`, `artifacts/`, `.pext`, or `.pthm`.
- Never push, tag, or cut a release from a PR — maintainers handle
  `{key}-v{version}` tags and PlayniteAddonDatabase submissions.
