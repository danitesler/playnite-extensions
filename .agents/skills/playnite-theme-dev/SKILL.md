## Rules that keep coming back

- **Running & launching indicators** ([contract](../../../docs/themes/reference.md#running-game-indicator), [motion kit & overlap rules](../../../docs/themes/running-motion.md)):
  - Frame and tint the whole row, cover, and game-page action cell in the item's real geometry above selection/hover layers (`Margin="4"` inset on covers), using a dedicated `RunningIndicatorBrush` distinct from Play, selection, hover, and filter accent.
  - `PART_ButtonContextAction` uses `Style="{DynamicResource PlayButton}" Tag="ContextAction"`, hiding Play-only glyphs on that Tag and filling the solid plate with `RunningIndicatorBrush` while launching/running (darkened via `RunningBreath` scrim so labels keep >= 4.5:1 contrast, 3:1 large bold floor).
  - Launching is a progress sweep (`RunningScan` gradient mask + `RunningFill` foot line + reacting motif, 1.4-2s loop); running is a quiet idle pulse (frame 0.7-1 + idling motif, 2.4-4s).
  - Running hover shows `{DynamicResource LOCCancelLabel}` + `RunningHoverDim` only on the button itself (`RelativeSource Self`, never `TemplatedParent`), setting `PlayContent` `Visibility="Hidden"` (never `Collapsed`) so the button never resizes. Reserve `PlayRoom` / `RowRoom` padding from `RunningLabelOverlapRegressionTests.ps1` so marks never touch labels, and inspect `RunningMotionFrames.ps1 -Keys <key> -OutDir <scratch>`.
- **Top bar progress** (`PART_ProgressGlobal` in `Views/TopPanel.xaml`): give `PART_TextProgressText` at least 12px side margin and set `Height="12"` on `PART_ProgressGlobal` (keep the shared `ProgressBar` template at `MinHeight="8"` with `Height="{TemplateBinding Height}"` so dialogs stay 8px).
- **Settings window** ([Settings screens](../../../docs/themes/settings-screens.md)): wrap a hidden `PART_TextTitle` inside a `Visibility="Collapsed"` parent (Playnite forces `PART_TextTitle` visible when a window has a `Title`); keep Settings/Add-ons section rows bare 28px lines at rest (no idle box/border) with opacity-animated hover wash and selected wash + 2px accent bar.
- **Control template performance**: keep inactive hover/pressed/selected/halo layers `Visibility="Collapsed"` at rest (toggling `Visible` at `0:0:0` on enter and `Collapsed` on exit), share `ImageBrush` / `LinearGradientBrush` opacity masks as `Local*` resources in `Common.xaml`, and set `MinWidth` on the game-page Play / ContextAction cell wide enough for `LAUNCHING` / `RUNNING` + the running strip.
- **WPF runtime crash traps** (enforced by `Test-WpfRuntimeTraps` in `validate-extension.ps1`):
  - **`WindowDesignStyle` must NOT be `BasedOn="{StaticResource StandardWindowStyle}"`** (`Window` vs `WindowBase` target type throws `InvalidOperationException` on `Style.Seal()`). Define `WindowDesignStyle` standalone.
  - **`ListBox` must set `ScrollViewer.CanContentScroll="True"`** (and `BasedOn="{StaticResource BaseStyle}"`), or Playnite's Grid view `VirtualizingWrapPanel` crashes on view switch.
  - **`PasswordBox` has no `VerticalScrollBarVisibility` / `HorizontalScrollBarVisibility`**: set `VerticalScrollBarVisibility="Hidden" HorizontalScrollBarVisibility="Hidden"` explicitly on `PART_ContentHost` instead of `TemplateBinding`.
  - **Never write `TextBlock.TextTrimming` or `TextBlock.TextWrapping` as attached attributes on `ContentPresenter`**: apply them via `<ContentPresenter.Resources><Style TargetType="TextBlock">...</Style></ContentPresenter.Resources>`.
  - **Verify live Playnite startup in `%APPDATA%\Playnite\playnite.log`** after `build-theme.ps1 -Extension <key> -Launch`: confirm `Application ... started` with zero `Unhandled exception occured` lines.

## Main menu mark (required)

Every theme draws its own animated main menu mark (hover plus menu-open animation, unique to the theme's motif and motion, one shared `Local<Name>MenuMarkTemplate` in `Common.xaml` used by `Sidebar.xaml` and `TopPanel.xaml`). Follow `docs/themes/menu-mark.md`, copy only the mechanics from Cloudbank, and verify hover and open live before calling the theme done.

## Menu item icons (required)

Every theme draws its own 24 bare, full-frame menu item icons, never Playnite's stock icofont glyphs, never wrapped in a background badge/plate, and never another theme's set recoloured. Write `art/menu-icons.json` (pure icon style, fill/finish, contour contrast, palette and metaphor variants from the theme's source), run `node scripts/render-menu-icons.mjs <Theme> --sheet`, and review the sheet at the real 16px on both rest and hover plates. Rules, recipe fields and the glyph kit: `docs/themes/menu-icons.md`.
